# 07　除錯 SOP：定位問題的方法

> 對應原本需求的《16 如何修 bug》《17 如何判斷錯誤發生在哪一層》《31 常見錯誤與處理方式》與「第九階段」。
>
> 這一章教的是**方法**，不是背答案。答案會隨著套件更新而改變，方法不會。

---

## 1. 除錯的總原則：先分層，再縮小

你的工具由下往上是這樣疊起來的。**錯誤一定發生在其中某一層。**

```
 ┌──────────────────────────────────────────────┐
 │ 第 6 層  AI 聽寫與硬體                          │  faster-whisper、CUDA、whisper.cpp、ffmpeg
 ├──────────────────────────────────────────────┤
 │ 第 5 層  外部服務                               │  YouTube、yt-dlp、youtube-transcript-api、Hugging Face
 ├──────────────────────────────────────────────┤
 │ 第 4 層  畫面（瀏覽器裡的 JavaScript）           │  ui.html
 ├──────────────────────────────────────────────┤
 │ 第 3 層  本機伺服器                             │  Handler、serve、/api/*
 ├──────────────────────────────────────────────┤
 │ 第 2 層  Python 程式本身                        │  ytscript.py 能不能被載入
 ├──────────────────────────────────────────────┤
 │ 第 1 層  啟動器                                 │  桌面捷徑、start.vbs、start.sh
 ├──────────────────────────────────────────────┤
 │ 第 0 層  系統與環境                             │  Python、pip 套件、Termux、驅動
 └──────────────────────────────────────────────┘
```

### 五個「分層探針」——每一個都能一次排除好幾層

| 探針 | 怎麼做 | 如果成功，代表… | 如果失敗，問題在… |
|---|---|---|---|
| **① 自我檢查** | `python tools/selfcheck.py` | 第 0、2、3 層大致正常 | 看哪一項失敗 |
| **② 疑難排解.bat**（電腦）／直接在 Termux 跑（手機） | 雙擊 `疑難排解.bat` 或 `cd ~/transcript && python ytscript.py` | 第 1 層以上能啟動 | 看視窗裡的錯誤 |
| **③ 命令列模式**（跳過畫面） | `python ytscript.py "影片網址"` | 第 2、5、6 層正常 → **問題在畫面或伺服器（第 3、4 層）** | 問題在第 5、6 層（或第 2 層） |
| **④ 瀏覽器 F12** | 按 `F12` → Console 分頁看紅字；Network 分頁看請求 | — | Console 紅字 → 第 4 層；Network 裡 `/api/*` 失敗 → 第 3 層 |
| **⑤ 退回舊版測試** | `git switch --detach 上一個tag` 再試一次 | 舊版正常 → **是最近的程式修改造成的** | 舊版也壞 → **是環境或外部造成的**（套件、YouTube、系統更新） |

**探針 ⑤ 是最有威力的一個。** 它一次回答「是我改壞的，還是外面變了？」這兩種的處理方式完全不同：
- 我改壞的 → `git diff` 找出改了什麼 → 修正或 `revert`
- 外面變了 → 更新套件、等 YouTube 恢復、或退回已知可用的套件版本（第 10 章）

（用完記得 `git switch main` 回來。）

## 2. 怎麼讀 Python 的錯誤訊息（Traceback）

在 `疑難排解.bat` 視窗或 Termux 裡，錯誤長這樣：

```
Traceback (most recent call last):
  File "C:\Users\User\projects\yt-transcript\ytscript.py", line 1930, in <module>
    serve(open_browser="--no-browser" not in args)
  File "C:\Users\User\projects\yt-transcript\ytscript.py", line 1883, in serve
    if not ensure_deps():
  File "C:\Users\User\projects\yt-transcript\ytscript.py", line 1697, in ensure_deps
    import youtube_transcript_api, yt_dlp
ModuleNotFoundError: No module named 'yt_dlp'
```

**讀法：從最下面往上讀。**

1. **最後一行是錯誤本身：** `ModuleNotFoundError: No module named 'yt_dlp'` → 缺 yt_dlp 套件
2. **往上找最後一個 `ytscript.py` 的行：** `line 1697, in ensure_deps` → 在 `ensure_deps` 函式的第 1697 行
3. 再往上是「誰呼叫它」：`serve` → 進入點

**如果最後幾行的檔案路徑不是 `ytscript.py`**（例如 `site-packages\yt_dlp\...`），
代表錯誤發生在**套件內部**，通常是套件版本問題或外部服務變了，不是你的程式碼錯了。

### 畫面紅框裡的錯誤

畫面上的紅框錯誤**不是** Traceback，是 `ytscript.py` 裡 `raise RuntimeError("...")` 寫好的訊息。
**最快的定位方法：複製紅框裡的一小段中文，到 `ytscript.py` 搜尋。** 就能找到是哪一行丟出的錯誤。

紅框底部的「技術細節」會列出每一層引擎各自失敗的原因：

```
技術細節：
引擎1 RequestBlocked: YouTube is blocking requests from your IP...
引擎2 DownloadError: ERROR: [youtube] xxx: Sign in to confirm you're not a bot
```

這告訴你「第 1 層被擋、第 2 層也被擋」→ 第 5 層（外部服務）問題。

## 3. 八種常見情境：一步一步找原因

### 情境 A：程式突然無法啟動（雙擊捷徑沒反應）

```
1. 雙擊 疑難排解.bat
   ├─ 視窗一閃就關／顯示 'python' 不是內部或外部命令
   │    → 第 0 層：Python 不見了或 PATH 壞了。重裝 Python，勾選 Add Python to PATH
   ├─ 視窗顯示 SyntaxError / IndentationError / NameError
   │    → 第 2 層：程式被改壞了。git status → git diff → git restore 或 git revert
   ├─ 視窗顯示 ModuleNotFoundError
   │    → 第 0 層：套件不見了。重跑 安裝.bat
   ├─ 視窗顯示「已啟動」但瀏覽器沒開
   │    → 手動開 http://localhost:8756；可能是預設瀏覽器設定問題
   └─ 疑難排解.bat 正常，但桌面捷徑不行
        → 第 1 層：start.vbs 或捷徑壞了
          · 跑一次 python tools/selfcheck.py，看「.bat／.vbs 維持純 ASCII」
          · 重跑 安裝.bat 重建捷徑
          · start.vbs 找的是 pythonw.exe；Anaconda 或特殊安裝路徑可能找不到（見 FindPythonW）
```

**手機版：** 在 Termux 直接打 `cd ~/transcript && python ytscript.py`，錯誤會直接顯示在畫面上。

### 情境 B：某個按鈕沒有反應

```
1. 按 F12 → Console 分頁 → 重新整理頁面 → 再按那個按鈕
   ├─ 有紅字（例如 Uncaught SyntaxError、Cannot read properties of null）
   │    → 第 4 層：ui.html 的 JavaScript 壞了
   │      · SyntaxError：多了或少了逗號、括號（最常見：PROMPT_HINTS 少一個逗號）
   │      · Cannot read properties of null：程式找不到某個 id → HTML 的 id 被改了
   │      · 跑 python tools/selfcheck.py，看「介面按鈕與後端一致」
   └─ 沒有紅字
        → 2. Network 分頁 → 再按一次按鈕
             ├─ 沒出現任何請求 → 按鈕的 addEventListener 沒綁上（搜尋那個按鈕的 id）
             ├─ /api/start 顯示紅色或 (failed) → 第 3 層：伺服器沒在跑 → 看情境 A
             └─ /api/start 是 200，但一直轉圈 → 第 5、6 層：去看疑難排解.bat 視窗的訊息
```

**所有按鈕同時沒反應** → 幾乎一定是 `<script>` 裡某處語法錯誤，整段 JavaScript 都沒執行。

### 情境 C：模型載入失敗

畫面或視窗出現和「模型」「model」「WhisperModel」「Hugging Face」有關的錯誤。

```
1. 是第一次用這個模型嗎？
   ├─ 是 → 需要下載（small 466 MB）。網路慢會很久；畫面應該每 5 秒顯示下載進度
   │       · 沒有進度 → 網路不通或 Hugging Face 被擋，換個網路試
   └─ 否 → 2
2. 模型檔可能下載到一半壞了
   → 刪掉模型資料夾讓它重新下載：
     電腦：C:\Users\你\.cache\huggingface\hub\models--Systran--faster-whisper-small
     手機：rm ~/.cache/whisper-cpp/ggml-tiny-q5_1.bin
3. 還是不行 → 看錯誤最後一行
   · MemoryError / 記憶體不足 → 改用「快速」模式（tiny）
   · 和 CUDA / cublas / cudnn 有關 → 情境 D
   · OMP: Error #15 → Anaconda 的 OpenMP 衝突，見 _import_whisper_first() 的註解。
     正常情況程式已經處理了；如果出現，代表有人（或 AI）改動了 import 的順序
4. 跑 python tools/selfcheck.py --whisper 做完整測試
```

### 情境 D：GPU 桌機可以，筆電不行（或反過來）

**先記住：兩台的程式碼完全相同。** 所以差異一定來自「環境」，不是程式碼。

```
1. 兩台都跑 python tools/selfcheck.py
   比較「這台機器的硬體路徑」那一行：
   桌機：運算裝置：CUDA（int8_float32）；「準確」模式會用的模型：small
   筆電：運算裝置：CPU（int8）；「準確」模式會用的模型：small 或 tiny

2. 兩台都跑 git log --oneline -1
   → 版本號不一樣？筆電 git pull

3. 比較套件版本（兩台都跑）：
   python -m pip list
   → 把兩台的結果都貼給 AI，請它找差異

4. 只有沒字幕的影片在筆電失敗？
   → 筆電可能沒裝 faster-whisper（安裝.bat 的 [2/4] 失敗了）
   → python -m pip install faster-whisper

5. 筆電慢到像當掉？
   → 正常現象：CPU 比 GPU 慢很多。用「快速」模式
   → 記憶體小於 4 GB 的筆電，程式會自動改用 tiny

6. 反過來：桌機 GPU 突然不能用、變很慢
   → selfcheck 顯示 CPU？代表 GPU 偵測失敗了
   → 常見原因：NVIDIA 驅動更新、nvidia-cublas-cu12 / nvidia-cudnn-cu12 被升級或移除
   → 退回已知可用的版本：python -m pip install -r requirements/whisper.txt -r requirements/gpu.txt
   → 程式設計上 GPU 失敗會自動改用 CPU，所以功能不會壞，只是變慢
```

### 情境 E：手機版突然錯誤

```
1. 在 Termux 裡直接執行，看完整錯誤：
   cd ~/transcript && python ytscript.py

2. 錯誤含 CANNOT LINK EXECUTABLE / library "xxx.so" not found
   → Termux 系統套件升級到一半。重跑：
     cd ~/transcript && bash android/install.sh
     （它的第 [2/8] 步會整包升級修復）

3. 只有沒字幕的影片失敗，訊息是「找不到 whisper.cpp 執行檔」或「需要 ffmpeg」
   → 手動測試這兩個：
     ffmpeg -version
     whisper-cli --help
   → 任一個失敗 → bash android/install.sh 重跑
   → 看安裝記錄：cat ~/install-log.txt | tail -50

4. 最近 git pull 過？
   → python ~/transcript/tools/selfcheck.py
     看「手機啟動器指向這個資料夾」—— 失敗代表還是舊的安裝方式，重跑一次 bash android/install.sh

5. 跑到一半手機休眠就斷掉
   → 設定 → 應用程式 → Termux → 電池 → 不最佳化／無限制

6. 手機的錯誤和電腦完全一樣（例如 Sign in to confirm）
   → 不是手機的問題，是第 5 層，看情境 I
```

### 情境 F：更新套件後程式壞掉

```
1. 確認是套件造成的：
   git log --oneline -3     → 程式最近沒改？那就是套件或外部
2. 看是哪個套件：
   錯誤訊息最後幾行的路徑裡有 site-packages\某套件名 → 就是它
3. 查它現在的版本：
   python -m pip show 套件名
4. 退回已知可用的版本：
   python -m pip install 套件名==舊版本號
   （實測過的版本號在 requirements/ 裡；或整組退回：
    python -m pip install -r requirements/whisper.txt -r requirements/gpu.txt）
5. python tools/selfcheck.py --online
```

**⚠️ 例外：yt-dlp 通常不要退版。** YouTube 一直在改，yt-dlp 舊版反而會抓不到。
yt-dlp 出問題時，**往前更新**才是正解：`python -m pip install --upgrade -r requirements/core.txt`

### 情境 G：GitHub 更新（git pull）後本機出問題

```
1. 看這次 pull 帶來了什麼：
   git log --oneline -5
   git diff HEAD~1 --stat          （上一次到這一次改了哪些檔案）
2. 有改到安裝腳本或新增套件？ → 重跑 安裝.bat（手機：bash android/install.sh）
3. 退回 pull 之前的版本確認：
   git switch --detach HEAD~1      （上一個版本）
   → 能用 → 是新版程式的問題 → git switch main → 用 git revert 撤銷那次修改
   → 也不能用 → 不是 pull 造成的，是環境問題
   用完 git switch main
4. 手機：selfcheck「手機啟動器指向這個資料夾」要通過；並確認程式有重新啟動
5. 電腦：確認舊的伺服器已經關掉（工作管理員結束 pythonw.exe），再重新開
```

### 情境 H：AI 修改後原本功能壞掉

**這是最容易處理的情境，因為你知道是什麼改變造成的。**

```
1. git diff   → 看 AI 到底改了什麼
   · 有沒有刪掉你沒要求刪的東西？（大片紅色）
   · 有沒有改到你沒提到的函式？
   · 有沒有改掉「先前…」「實測…」「注意」這類註解旁邊的程式？
2. python tools/selfcheck.py → 哪一項失敗？
3. 決定：
   · 簡單的錯（少逗號、縮排）→ 自己修
   · 不確定 → 把「git diff 的結果 + selfcheck 輸出 + 錯誤訊息」一起貼給 AI（第 08 章提示詞 C）
   · AI 修了兩輪還是不行 → 放棄這次修改：
       還沒 commit：git restore 檔名
       已經 commit：git revert 編號
       在分支上：git switch main → git branch -D 分支名
```

**規則：同一個問題，AI 修兩輪還修不好，就先退回，換個方式描述需求重新來。**
不要讓 AI 在壞掉的程式上一直疊修改，那只會越來越亂。

### 情境 I：突然所有影片都抓不到字幕（最常見）

```
1. 先更新這兩個套件（九成的情況到這裡就解決了）：
   python -m pip install --upgrade -r requirements/core.txt
   手機：cd ~/transcript && pip install --upgrade -r requirements/core.txt
2. 錯誤訊息是「這部影片其實有字幕…但現在下載不到」或 HTTP 429
   → YouTube 暫時限流。等幾分鐘到一小時
3. 錯誤含 Sign in to confirm you're not a bot / RequestBlocked / IpBlocked
   → YouTube 懷疑你是機器人
   · 有開 VPN？關掉
   · 換個網路（例如手機熱點）試試
   · 等一陣子
4. 只有某一部影片失敗 → 那部影片可能是私人、會員限定、已刪除、地區限制
5. 只有非 YouTube 網站失敗 → 該網站可能需要登入；更新 yt-dlp
```

## 4. 常見錯誤對照表

| 錯誤訊息（關鍵字） | 哪一層 | 原因 | 處理 |
|---|---|---|---|
| `'python' 不是內部或外部命令` | 0 | Python 沒裝或沒加 PATH | 重裝 Python，勾 Add to PATH |
| 小視窗「Python was not found」 | 1 | start.vbs 找不到 pythonw.exe | 同上 |
| `ModuleNotFoundError: No module named 'xxx'` | 0 | 套件沒裝 | `python -m pip install xxx`，或重跑安裝 |
| `SyntaxError`、`IndentationError` | 2 | 程式碼寫錯（常是貼上 AI 的程式時） | `git diff` 看改了什麼；`git restore` |
| `NameError: name 'xxx' is not defined` | 2 | 打錯字或少了 import | 搜尋 xxx 看哪裡拼錯 |
| `KeyError: 'xxx'` | 2 | 從字典拿一個不存在的欄位 | 通常是 AI 把 `.get("xxx")` 改成了 `["xxx"]` |
| `AttributeError: ... has no attribute 'xxx'` | 0／5 | 套件版本不對（用法改了） | selfcheck「套件是實測過的版本」；或 `pip show 套件` 對照 `requirements/` |
| 小視窗「連接埠 8756 無法使用」 | 3 | 其他程式佔用 | 重開機；或改 `DEFAULT_PORT` |
| 畫面「與程式的連線中斷」 | 3 | 伺服器停了或當掉 | 用 疑難排解.bat 啟動看錯誤 |
| 畫面「查無此工作」 | 3 | 轉錄途中伺服器重啟了 | 重新轉錄 |
| F12 Console：`Uncaught SyntaxError` | 4 | ui.html 的 JavaScript 語法錯 | `git diff ui.html` 找少的逗號、括號 |
| F12 Console：`Cannot read properties of null` | 4 | JavaScript 找不到某個 id | HTML 的 id 被改了或刪了 |
| `HTTP Error 429`、「其實有字幕…下載不到」 | 5 | YouTube 限流 | 等待 |
| `Sign in to confirm you're not a bot` | 5 | YouTube 擋 IP | 關 VPN、換網路、更新 yt-dlp |
| `RequestBlocked`、`IpBlocked` | 5 | youtube-transcript-api 被擋 | 會自動改用引擎 2；都失敗就等待 |
| 「這部影片沒有任何字幕，需要用 AI 聽寫，但還沒安裝聽寫元件」 | 0 | 沒裝 faster-whisper | `python -m pip install faster-whisper` |
| `Library cublas64_12.dll is not found` | 6 | CUDA 函式庫找不到 | 程式應自動改用 CPU；要恢復 GPU：`python -m pip install -r requirements/whisper.txt -r requirements/gpu.txt` |
| 「顯示卡無法使用（xxx），改用 CPU」 | 6 | GPU 載入失敗，已自動退回 CPU | 功能正常只是慢；同上恢復 |
| `OMP: Error #15` 或程式無聲消失 | 6 | Anaconda OpenMP 衝突 | 見 `_import_whisper_first()` 註解；檢查 import 順序有沒有被改 |
| 「找不到 whisper.cpp 執行檔」 | 6 | 手機 whisper.cpp 沒編譯成功 | `bash android/install.sh` |
| 「需要 ffmpeg 才能轉換音訊」 | 6 | 手機沒 ffmpeg | `pkg install ffmpeg` |
| 「AI 聽寫沒有產生任何文字」 | 6 | 音訊無聲，或模型太大記憶體不足 | 用「快速」模式 |
| `CANNOT LINK EXECUTABLE` | 0 | Termux 升級不完整 | `bash android/install.sh` |
| 輸出是簡體中文 | 0 | 沒裝 opencc | `pip install opencc-python-reimplemented` |
| AI 聽寫非常慢（桌機） | 6 | GPU 沒用上 | selfcheck 看硬體路徑那行 |

## 5. 修 bug 的通用流程

```
① 重現：確定「做什麼事、用哪部影片、在哪台機器」會出錯。記下來。
② 分層：用第 1 節的五個探針，找出是哪一層。
③ 判斷：是我改壞的？還是外面變了？（探針 ⑤）
④ 決定修或退：
   · 外部問題（YouTube、套件）→ 更新或退套件版本，通常不改程式
   · 程式問題、而且我知道在哪 → 開分支修
   · 程式問題、不知道在哪 → 找 AI（第 08 章提示詞 B）
   · 修不好 → 退回上一個 tag，工具先能用再說
⑤ 修完：selfcheck → 用 ① 記下的方式重現一次，確定好了 → commit
⑥ 記錄：commit 訊息寫清楚「症狀 + 原因 + 怎麼修」，一年後的你會感謝現在的你
```
