## 30 秒看懂你的工具

- **它是什麼：** 一個在自己電腦上跑的小網站。貼影片連結 → 產生給 AI 分析用的逐字稿。
- **核心只有兩個檔案：** `ytscript.py`（大腦）與 `ui.html`（畫面）。**三台機器共用同一份。**
- **三台的差別只在：** 安裝方式、啟動方式、AI 聽寫引擎（電腦 faster-whisper／手機 whisper.cpp）、有沒有 GPU。
- **所有東西都在 GitHub：** `https://github.com/door410/transcript`
- **改壞了不用怕：** Git 記得每一個版本，隨時可以退回去。

## 三條鐵則（其他都忘了，也要記得這三條）

1. **改之前先存檔。** `git switch -c 分支名`，或至少 `git commit`。有存檔點，什麼都救得回來。
2. **只在桌機改程式。** 筆電和手機只做 `git pull`，pull 完重新啟動程式就是新版。
3. **改完跑 `python tools/selfcheck.py`，全部通過才 commit。**

## 如果 Claude 消失了，我該怎麼繼續維護

### 你不會失去什麼

- **工具本身。** 它完全在你的機器上執行，不需要任何 AI 就能運作。
- **程式碼與完整歷史。** 在 GitHub，也在每一台 clone 過的機器上。
- **維護知識。** 在這份手冊，以及 `ytscript.py` 的註解裡（那些「先前…實測…」的註解就是過去所有除錯經驗的紀錄）。

### 你會失去什麼

- 「寫比較複雜的新功能」的能力會下降。免費 AI 仍然能處理大部分小修改，但遇到 GPU、手機編譯這類問題，可能要試很多次。

### 具體怎麼做

1. **日常維護不需要 AI：**
   - 抓不到字幕 → 更新 yt-dlp（第 07 章情境 I）
   - 更新後壞了 → 退回已知可用版本（第 10 章）
   - 改壞了 → Git 退版（第 05 章 §8）
   - 改提示詞、改畫面文字 → 直接改字串（第 04 章概念 3）

2. **需要 AI 時，換任何一個免費 AI（ChatGPT、Gemini、Copilot 等）：**
   - 開新對話 → 貼第 08 章的「專案背景卡」→ 用對應的提示詞模板
   - 只給相關的那一段程式碼，不要整個檔案
   - **永遠自己跑 selfcheck、自己看 diff**。不管 AI 多有自信，都只相信執行結果

3. **遇到修不好的問題：**
   - 先退回最近的穩定 tag，**讓工具先能用**
   - 問題留著，之後有時間、或有更好的 AI 時再處理
   - 「停在一個能用的舊版本」永遠是可以接受的選擇

4. **定期保養（每幾個月一次，或每次大改之後）：**
   - [ ] 三台跑 selfcheck
   - [ ] 打一個穩定版 tag
   - [ ] 升級過套件而且測試通過的話，更新 `requirements/` 裡的版本號
   - [ ] `git bundle create` 做一份離線備份（第 10 章 §6）
   - [ ] 程式有大改的話，請 AI 更新第 03 章與背景卡（第 08 章提示詞 G）
