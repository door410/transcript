## 1. 新增功能 SOP（每次照做）

```
 ① 描述需求        一句話寫下「我想要什麼」，以及「不想動到什麼」
 ② 判斷範圍        三台都要？只有 GPU？只有手機畫面？（第 02 章 §5 對照表）
 ③ 找位置          用對照表找到檔案與函式，在 VS Code 裡打開確認
 ④ 開分支          git switch main → git pull → git switch -c feature/名稱
 ⑤ 改              自己改，或用第 08 章的提示詞請 AI 改
 ⑥ 看 diff         git diff（或 VS Code 原始檔控制）——只改了該改的地方嗎？
 ⑦ 自我檢查        python tools/selfcheck.py → 全部通過
 ⑧ 實際使用        疑難排解.bat 啟動 → 用新功能 → 也用一次舊功能
 ⑨ 存檔            git add 檔名 → git commit -m "說明"
 ⑩ 併回主線        git switch main → git merge feature/名稱 → 再跑一次 selfcheck
 ⑪ 上傳            git push
 ⑫ 同步其他兩台    筆電、手機 git pull，重新啟動程式
 ⑬ 其他兩台測試    第 09 章的檢查表
 ⑭ 打 tag（選用）  三台都 OK → git tag -a v日期 → git push origin v日期
```

### 哪一步最常被跳過、跳過的後果

| 跳過 | 後果 |
|---|---|
| ④ 開分支 | 改壞了只能手動一行一行改回去 |
| ⑥ 看 diff | AI 順手刪掉一段防呆，三個月後才發現某種影片會失敗 |
| ⑧ 用一次舊功能 | 新功能正常，但原本的功能壞了 |
| ⑫ 同步後重新啟動 | 程式還開著的話，跑的仍是舊版的 Python（畫面會變，功能不會） |

## 2. 完整實作範例：新增「考試複習」分析模式

> 這個範例**已在 2026-09-24 實際做過一次**（在一條臨時分支上，做完已刪除，main 沒有這個功能）。
> 下面每一步的輸出都是實際的結果。你可以照著做一次當練習；做完要保留或丟掉都可以。

### ① 描述需求

> 我想在「分析模式」多一個選項「考試複習」。選它的時候，輸出最前面的 AI 指示要改成：
> 整理必考重點、名詞解釋、易混淆處，並出 5 題附解答的選擇題。
> **不要動到**原本的深度學習、快速摘要、純逐字稿三種模式。

### ② 判斷範圍

- 這是「給 AI 的指示」→ 在 `ytscript.py`，三台共用
- 還需要一顆按鈕 → 在 `ui.html`，三台共用
- 不需要新套件 → 安裝腳本不用動
- **結論：三台都會有；只要改一次；另外兩台 git pull 即可**

### ③ 找位置

查第 02 章 §5.1：「新增一種分析模式」→
`ytscript.py` 新增 `PROMPT_XXX` 並加入 `PROMPTS`；`ui.html` 的 `segPrompt` 加一顆按鈕、`PROMPT_HINTS` 加說明。

在 VS Code 裡確認：

1. `ytscript.py` 搜尋 `PROMPTS =` → 第 168 行：
   ```python
   PROMPTS = {"deep": PROMPT_DEEP, "quick": PROMPT_QUICK}
   ```
2. 搜尋 `PROMPTS[`，看它被誰用 → `build_markdown`（第 1241 行）和 `split_parts`（第 1501 行）。
   兩個都是用 `if mode in PROMPTS:` 判斷，**所以只要把新模式加進 `PROMPTS`，兩邊都會自動支援**，不用改這兩個函式。
3. `ui.html` 搜尋 `segPrompt` → 第 152 行，三顆按鈕，每顆有 `data-v="..."`
4. `ui.html` 搜尋 `PROMPT_HINTS` → 第 257 行

**這一步的觀念：** 按鈕上的 `data-v="exam"` → `options()` 送出 `prompt_mode: "exam"` → Python `PROMPTS["exam"]`。
**三個地方的名字（`exam`）必須完全一樣。**

### ④ 開分支

```bash
cd C:\Users\User\projects\yt-transcript
git status
git switch main
git pull
git switch -c feature/exam-mode
```

### ⑤ 改——第一處：`ytscript.py`

在 `PROMPT_QUICK` 結束的 `"""` 之後、`PROMPTS = ...` 之前，加入新的提示詞；並把 `PROMPTS` 那行加上 `"exam"`：

```python
PROMPT_EXAM = """\
以下是一部 YouTube 影片的逐字稿。我要準備考試，請用繁體中文幫我整理成複習講義：

1. **必考重點** —— 列出 5～10 個最可能被考的觀念，每個附時間戳
2. **名詞解釋** —— 影片中的專有名詞，各用一句話解釋
3. **易混淆處** —— 哪些觀念容易搞混？差別在哪？
4. **練習題** —— 出 5 題選擇題，答案與解析放在最後

引用時請附上時間戳（例如 `[12:34]`）。影片沒講到的不要自己補。
"""

PROMPTS = {"deep": PROMPT_DEEP, "quick": PROMPT_QUICK, "exam": PROMPT_EXAM}
```

### ⑦（先跑一次）自我檢查——故意只改一半

只改了 Python、還沒改畫面時跑一次，看看會怎樣：

```bash
python tools/selfcheck.py
```

實際輸出：

```
  [失敗] 介面按鈕與後端一致
         原因：AssertionError: 介面按鈕 ['deep', 'none', 'quick'] 與後端 PROMPTS ['deep', 'exam', 'none', 'quick'] 不一致
有 1 項失敗：介面按鈕與後端一致
→ 先不要 commit。把上面整段輸出貼給 AI，請它解釋原因。
```

**這就是自我檢查的用處：** 它抓到「後端有 exam，畫面沒有按鈕」。
如果是 AI 幫你改、只改了一半，你會在這裡發現。

### ⑤ 改——第二處：`ui.html`

**(a) 按鈕**（第 152 行附近，在「快速摘要」下面加一行）：

```html
          <div class="fi-seg" id="segPrompt">
            <button class="fi-seg__btn is-on" data-v="deep">深度學習</button>
            <button class="fi-seg__btn" data-v="quick">快速摘要</button>
            <button class="fi-seg__btn" data-v="exam">考試複習</button>
            <button class="fi-seg__btn" data-v="none">純逐字稿</button>
          </div>
```

**(b) 說明文字**（第 257 行附近，在 `quick:` 那行下面加一行）：

```javascript
const PROMPT_HINTS = {
  deep:  '完整的三階段分析：...',
  quick: '精簡版：...',
  exam:  '考試用：必考重點、名詞解釋、易混淆處，加上 5 題附解答的選擇題。上課影片、考前複習時用。',
  none:  '只給逐字稿本身，不附任何指示。你想自己下提示詞時用。',
};
```

注意每行最後的**逗號**。JavaScript 的清單中每一項後面都要有逗號，少了畫面會整個壞掉（按鈕全部沒反應）。

### ⑥ 看 diff


實際輸出：


**怎麼判斷這個 diff 是對的：**
- 只有 2 個檔案 ✅（符合 ② 的判斷）
- 新增 13 行、刪除 1 行 ✅（被刪的那 1 行是舊的 `PROMPTS = ...`，被新的取代）


## 3. 修改既有功能 SOP

和新增功能相同，只多兩件事：

1. **改之前先讀那段程式的註解。** 這個專案的註解記錄了大量「以前這樣寫結果壞掉」的經驗
   （搜尋「先前」「實測」「注意」「陷阱」就會看到）。**那些註解就是這個專案的維護知識。**
2. **改完要測「原本會觸發這段程式的情況」。** 例如改了 `has_caption_tracks`，就要測「有字幕的影片」「沒字幕的影片」「bilibili 影片」三種。

### 常見修改的測試重點

| 改了哪裡 | 至少要測 |
|---|---|
| 提示詞 | 該模式轉一次，看輸出 |
| `build_markdown` | 短影片一次、**超過 1 小時的長影片一次**（因為長影片走 `split_parts`） |
| `clean_segments`、`NOISE_PAT`、`FILLER_*` | 中文影片、英文影片各一次，確認正常內容沒被刪 |
| 引擎 1／2 | 有人工字幕的影片、只有自動字幕的影片、非 YouTube 影片（bilibili） |
| 引擎 3（whisper） | 沒字幕的影片：桌機（GPU）、筆電（CPU）、手機各一次；`--whisper` 級自我檢查 |
| GPU 那一區 | 桌機 GPU + 筆電 CPU 兩台都要測；`python tools/selfcheck.py --whisper` 要看到「使用顯示卡加速」 |
| `ui.html` | 桌機寬螢幕 + 手機（或 F12 手機模擬）；按鈕都按一次；**深色模式也看一次** |
| `tokens.css` | 淺色 + 深色模式 |
| `start.vbs`、`安裝.bat` | 重新雙擊捷徑、重新跑安裝；**selfcheck 會檢查純 ASCII** |
| `android/install.sh` | 在手機上完整重跑一次，看最後的 `[8/8] 端對端驗證` |

## 5. 「需要新套件」的功能要多做什麼

假設新功能需要 `pip install 某套件`：

1. **先確認三台都裝得起來。** 特別是手機：Android 上很多套件沒有預編譯版本（faster-whisper 就是例子）。
   在 Termux 先手動 `pip install 某套件` 試試看。
2. **把它加進 `requirements/`**（不用改任何安裝腳本，三個安裝管道都從這裡讀）：
   - 三台都要用 → `requirements/core.txt`
   - 只有電腦要用 → `requirements/whisper.txt`
   - 寫成 `套件名==版本`（鎖定你測試過的版本）。⚠️ 這些檔案必須**純 ASCII**，註解不能寫中文
   - 例外：`ensure_deps()` 裡「開頭檢查有沒有裝」的那行 `import` 若也要檢查新套件，要一起加
3. **在程式裡用「用到才 import」的方式**，並處理沒裝的情況（參考 `to_traditional()` 對 opencc 的做法：沒裝就跳過，不讓整個工具壞掉）。
4. 跑 `python tools/selfcheck.py`，「套件是實測過的版本」會確認你寫的版本和實際裝的一致。
