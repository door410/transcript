# 11　專案結構的問題與改善建議

> 你要求「如果專案結構本身有不利於長期維護的地方，請直接指出來」。這一章就是。
> 每一項都是讀過實際程式碼、實際執行過之後的判斷，並標示嚴重程度與建議處理順序。
> **不需要一次全部處理。** 很多項目「知道就好」，不處理也不會出事。

---

## 先講整體評價

**比一般 AI 生成的專案好很多。** 具體來說：

- ✅ **核心程式三台共用，沒有三份重複的程式碼。** 這是最重要的一點。
  （9/22 曾經出現過一份 2,241 行的 `mobile/app/ytscript.py` 重複版本，已在 `1892eae` 吸收有用部分後刪除。這個決定是對的。）
- ✅ **功能分區清楚**，用分隔線切成十一區，每區職責單一
- ✅ **註解記錄了「為什麼」而不只是「做什麼」**，而且有大量實測數據與踩坑紀錄——這是這個專案最有價值的維護資產
- ✅ **錯誤處理有分層的 fallback**：引擎 1 失敗 → 引擎 2 → 引擎 3；GPU 失敗 → CPU；套件沒裝 → 跳過該功能
- ✅ **沒有不必要的框架**（沒有 React、Flask、資料庫），依賴少，零基礎的人也能讀
- ✅ **有 `.gitattributes` 處理 Windows 換行問題**，有 `.gitignore`

**主要弱點集中在「環境可重現性」和「文件同步」，而不是程式碼品質。**

## 問題清單

### 🔴 高：會實際造成損失，建議盡快處理

#### 1. ~~套件版本完全沒有鎖定~~

- **現況：** `安裝.bat`、`ensure_deps()`、`android/install.sh` 全部 `pip install --upgrade`，永遠裝最新版
- **後果：** 重新安裝（換電腦、重灌）時，可能裝到不相容的新版。你無法重現「上次能用的環境」，也不知道是哪個套件造成的
- ✅ **已解決（2026-09-24）：** 新增 `requirements/`（core／whisper／gpu 三個檔案），三個安裝管道都改成從這裡讀。
  AI 聽寫與 CUDA 套件完全鎖定；yt-dlp 只設下限（必須追著 YouTube）；youtube-transcript-api 限制在 1.x。
  鎖定版本裝不起來時，`安裝.bat` 會警告並退回最新版。selfcheck 新增「套件是實測過的版本」檢查。
  手機的 whisper.cpp 也固定在 v1.9.4。詳見第 10 章 §1～3
- **仍需你做的：** 筆電、手機各跑一次 selfcheck，確認版本檢查通過

#### 2. 沒有任何自動測試

- **現況：** 改完程式只能靠手動使用判斷
- **後果：** AI 修改時順手弄壞的舊功能不會被發現
- **已做的處理：** 新增 `tools/selfcheck.py`（第 09 章）
- **你要做的：** 每次改完都跑。新增功能時，可以請 AI 一併在 selfcheck 加一項檢查

#### 3. ~~沒有 tag，沒有「穩定版」的標記~~

- **原本：** 13 個 commit，沒有任何 tag，要退版只能靠讀 commit 訊息猜
- ✅ **已解決（2026-09-24）：** 建立第一個 tag `v2026.09.24`（桌機實測通過）
- **之後：** 每次三台都測過，就再打一個（第 05 章 §9）

#### 4. ~~手機的 `Android手機安裝說明.md` 描述的流程已經不能用~~

- **現況：** 這份文件描述的是舊流程：從 Google Drive 下載 `手機安裝包.zip` → 執行 `/sdcard/Download/install.sh` → 「腳本會自動解壓縮安裝包」
- **實際：** 現在的 `android/install.sh` **不會解壓縮任何東西**，而且它要求 `ytscript.py` 在「install.sh 所在資料夾的上一層」。照舊文件做，會直接出現「找不到 ytscript.py」並結束
- **同樣的問題：** `build/make_single_file.py` 產生的 `手機安裝包.zip` 把 `install.sh` 放在 zip 的根目錄，和 `ytscript.py` 同一層——解壓後執行一樣會找不到
- **文件其他過時處：** 提到「點網頁最下方的『結束程式』」——這個按鈕已經不存在
- ✅ **已解決（2026-09-24）：**
  - `Android手機安裝說明.md` 整份改寫成 git clone 流程（8 個步驟、權限、桌面圖示、更新、常見問題）
  - `install.sh` 現在兩種版面都認得：repo 裡的 `android/install.sh`，或 zip 解壓後和 `ytscript.py` 同一層的 `install.sh`
  - `手機安裝包.zip` 一併帶上 `requirements/core.txt`；電腦版 zip 帶上 `requirements/` 與 `tools/selfcheck.py`（`安裝.bat` 需要它們）
  - 同時修正了 `安裝指南.md`（`[3/6]`、不存在的 `--no-whisper`）、`install.sh` 結尾指向不存在章節的訊息、README 的 `termux-stt` 錯誤說明

### 🟡 中：會造成困惑或浪費，但不會讓工具壞掉

#### 5. ~~手機的執行副本 `~/ytscript/` 與 repository 分離~~

- **原本：** `install.sh` 把程式**複製**到 `~/ytscript/` 執行，而不是直接從 `~/transcript/` 執行
- **後果：** `git pull` 之後，手機還在跑舊版，而且沒有任何提示。這是三台之中最容易「以為更新了其實沒有」的地方
- ✅ **已解決（2026-09-24）：** `install.sh` 產生的 `~/ytscript/start.sh` 改成直接執行 repo 裡的程式，
  並清掉舊的副本。之後手機只要 `git pull` + 重新啟動。selfcheck 的「手機啟動器指向這個資料夾」會檢查是否已換成新方式
- **仍需你做的：** 手機 `git pull` 後**重跑一次** `bash ~/transcript/android/install.sh`（一次性），然後跑 selfcheck
- ⚠️ 這個改動已在電腦上模擬測試（兩種版面、舊副本清除、啟動器內容），**尚未在真的手機上跑過**

#### 6. 手機下載了程式根本不會用的模型（浪費數百 MB）

- **現況：** 在手機上，「快速」與「準確」**兩個選項都會用 `tiny-q5_1`**（`default_model_size()` 在 Termux 一律回傳 `tiny`，再經 `GGML_QUANT` 換成量化版）
- **但 `install.sh` [6/8] 還會下載：**
  - `ggml-tiny.bin`（75 MB）：只被安裝腳本最後的自我測試使用
  - 依記憶體：`ggml-large-v3-turbo-q5_0.bin`（約 550 MB）或 `ggml-small-q5_1.bin`（181 MB）或 `ggml-base-q5_1.bin`：**程式從不使用**
  - `ggml-silero-v5.1.2.bin`（VAD 模型）：**程式從不使用**（`engine_whispercpp` 沒有傳 VAD 參數）
- **後果：** 手機多佔數百 MB 空間與下載流量；安裝訊息寫「【準確】模式用的模型」會讓人誤以為準確模式會用到它
- **原因推測：** 從 `mobile/install.sh` 移植過來時，對應的 Python 端邏輯（`mobile/app/ytscript.py` 的準確模式）沒有一起移植
- **建議（二選一，請 AI 協助）：** (a) 刪掉 install.sh 裡不用的下載；或 (b) 讓 `engine_whispercpp` 在「準確」模式真的使用較大的模型。無論哪一個，都要在手機實測

#### 7. 文件彼此矛盾、與程式不符

（2026-09-24 已修正手機相關的四處：README 的 termux-stt、安裝指南的 `[3/6]` 與 `--no-whisper`、install.sh 結尾訊息。以下是剩下的。）

| 位置 | 寫的 | 實際 |
|---|---|---|
| `README.md` 第 134～150 行 | 一段殘缺的表格，列出「時間戳」「段落長度」等選項 | 這些選項已經移除，這段是改版殘留 |
| `README.md` 第 259 行 | 模型「介面上可以手動切換」 | 介面只有快速／準確，不能選模型 |
| `安裝指南.md` 第 1 節 | 程式位置 `C:\Users\User\projects\yt-transcript` | 這是這台桌機的路徑，其他人／其他電腦不適用（對你自己沒問題） |

- **後果：** 一年後的你（或免費 GPT）讀到矛盾的文件，會不知道該相信哪個
- **建議：** 請 AI 依照本章列表逐項修正 README 與安裝指南（第 08 章提示詞 A，範圍限定在文件）

#### 8. 輸出格式的程式碼有兩份

- **現況：** `build_markdown()` 和 `split_parts()` 各自組 Markdown（標題、章節、逐字稿行的格式）
- **後果：** 改格式時只改一邊，長影片（超過約 3 萬 tokens）的輸出就會和短影片不一致
- **建議：** 不急著重構（重構本身有風險）。**知道要兩邊一起改就好**，已寫進第 02 章對照表

#### 9. 程式大量「吞掉」錯誤，而且沒有記錄檔

- **現況：** 很多地方是 `except Exception: pass`（出錯就當作沒事）。這是刻意的，讓工具在各種環境下都能「盡量繼續跑」
- **加上：** 桌面捷徑用 `pythonw` 執行，**沒有任何視窗或記錄檔**
- **後果：** 出問題時看不到原因，必須另外用 `疑難排解.bat` 重現一次
- **建議（選用）：** 讓程式把 `log()` 的訊息與錯誤同時寫進一個記錄檔（例如 `~/.cache/yt-transcript/last-run.log`）。這樣出錯後直接打開記錄檔就知道發生什麼事。這是對「沒有 Claude 的你」幫助很大的改善

#### 10. 設定值散落在兩個檔案

- **現況：** 沒有設定檔。有些設定在 `ytscript.py` 的大寫常數，有些（段落長度、快速模式的模型）寫死在 `ui.html` 的 `options()`
- **後果：** 例如想改段落長度，改 Python 的預設值不會有任何效果，因為畫面每次都送 45
- **建議：** 不需要重構。第 03 章 §7 的設定總表已經列出每個設定在哪裡

#### 11. 手機聽寫的時間戳精度（需要實測確認）

- **現況：** `engine_whispercpp()` 呼叫 whisper-cli 時帶了 `-nt`（`--no-timestamps`）。查 whisper.cpp 原始碼：JSON 輸出一律包含時間，但 `-nt` 也會讓解碼時不產生時間標記
- **可能的後果：** 手機 AI 聽寫的段落時間戳，精度可能只有約 30 秒（每個 30 秒視窗一段），而不是電腦版那樣逐句
- **怎麼確認：** 在手機上轉一部**沒字幕**的影片，看時間戳是不是幾乎都是 `00:00`、`00:30`、`01:00` 這種 30 秒的整數倍。是的話，請 AI 評估拿掉 `-nt` 的影響
- **影響程度：** 低。段落本來就是約 45 秒一段，30 秒精度對「回原片查證」仍然堪用

### 🟢 低：知道就好

#### 12. `ytscript.py` 是一個 1,930 行的單一檔案

- 伺服器、三個引擎、輸出格式都在同一個檔案裡
- **客觀判斷：以這個專案的規模，這不是問題，反而對你有利。** 單一檔案代表你只需要打開一個地方、AI 只需要看一個檔案、不會有「改了 A 檔忘了 B 檔」的問題
- **不建議拆檔。** 拆檔是一次大型重構，對零基礎維護者來說風險大於好處。**如果 AI 建議你拆，拒絕它**

#### 13. 畫面依賴 Google Fonts

- `ui.html` 第 8 行從網路載入字型。離線時會退回系統字型，功能不受影響，只是字型不同

#### 14. whisper.cpp 沒有固定版本

- ✅ 已解決（2026-09-24）：`install.sh` 固定取 `v1.9.4`（已確認有程式用到的所有參數），取不到才退回最新版
- 已經編譯過的手機不受影響（install.sh 偵測到已建置就跳過）；要換成固定版本需 `rm -rf ~/whisper.cpp` 後重跑

#### 15. 從 GitHub 網頁上傳檔案造成過分岔

- `e603011`、`1df5d26` 兩個「Add files via upload」commit，接著是合併 commit `6e60574`
- 這不是程式碼問題，是流程問題。第 02 章 §7 與第 05 章 §10 已經寫了規則：**不要從網頁上傳程式**

#### 16. `.claude/launch.json`

- Claude Code 專用的預覽設定。沒有 Claude 也不影響任何東西，可以留著

## 建議處理順序

| 順序 | 項目 | 誰做 | 時間 |
|---|---|---|---|
| ✅ | 手冊、selfcheck、#1、#3、#4、#5 | 已完成（2026-09-24） | — |
| 1 | 筆電 `git pull` → selfcheck；手機 `git pull` → 重跑一次 install.sh → selfcheck | 你 | 30 分鐘 |
| 2 | 三台都通過後打新的 tag | 你 | 5 分鐘 |
| 4 | 手機實測時間戳（#11） | 你 | 10 分鐘 |
| 5 | 修正過時文件（#4、#7） | 你 + AI（練習第 08 章流程的好題目，只動文件、風險極低） | 1 小時 |
| 6 | 加記錄檔（#9） | 你 + AI | 1～2 小時 |
| 7 | 手機模型下載整理（#6） | 你 + AI，要在手機實測 | 1 小時 |
| — | #8、#10、#12～16 | 不用處理 | — |

第 5 項特別適合當你「第一次自己用 AI 改東西」的練習：只改 `.md` 文件，就算改錯也完全不會影響工具運作。
