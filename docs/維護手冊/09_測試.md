# 09　三個版本的測試流程

> 對應原本需求的《29 三個版本的測試流程》。

---

## 1. 為什麼要有固定的測試流程

這個專案原本**沒有任何自動測試**。AI 改完程式後，只能靠「打開來用用看」判斷有沒有壞。
問題是：你用的那一下，通常只測到你剛改的功能，**被順手弄壞的舊功能不會被發現**。

所以 2026-09-24 新增了 `tools/selfcheck.py`。它不需要你懂程式，只要看最後一行是不是「全部通過」。

---

## 2. 自我檢查：三個等級

在專案資料夾裡執行：

| 指令 | 等級 | 時間 | 需要網路 | 什麼時候用 |
|---|---|---|---|---|
| `python tools/selfcheck.py` | 第 1 級 | 約 5 秒 | 不需要 | **每次改完程式、每次 git pull 之後** |
| `python tools/selfcheck.py --online` | 第 2 級 | 約 10 秒 | 需要 | 更新套件之後、懷疑抓不到字幕時 |
| `python tools/selfcheck.py --whisper` | 第 3 級 | 10 秒～數分鐘 | 需要 | 動到 AI 聽寫或 GPU、換電腦、更新 faster-whisper／CUDA 之後 |

### 它檢查什麼

| 項目 | 抓得到的問題 |
|---|---|
| 必要檔案都在 | 誤刪檔案 |
| 主程式可以載入 | 語法錯誤、縮排錯誤、貼上 AI 程式時的格式問題 |
| .bat／.vbs 維持純 ASCII | 在啟動器裡寫了中文（會讓 Windows 啟動器壞掉） |
| 網址解析 | YouTube 各種網址格式還認不認得 |
| 字幕清理與段落合併 | 雜訊、口頭禪、重複行的處理 |
| 三種字幕格式解析 | json3、srv1、SRT 的解析 |
| 輸出結構 | `assemble()` 回傳的欄位是否齊全（ui.html 需要它們） |
| 每一種分析模式 | 每個模式的提示詞是否正確出現 |
| 介面按鈕與後端一致 | ui.html 的按鈕、說明文字與 `PROMPTS` 是否對得上；重要元素的 id 還在不在 |
| 本機伺服器與 API | 真的啟動伺服器，確認網頁、樣式、`/api/ping`、`/api/start` 正常 |
| 這台機器的硬體路徑 | **只報告不判定**：GPU 或 CPU、會用哪個模型、手機的 whisper.cpp 與 ffmpeg 在不在 |
| 套件是實測過的版本 | 已安裝的套件和 `requirements/` 不一致（core.txt 不符＝失敗；whisper／gpu 不符＝只提醒） |
| 手機啟動器指向這個資料夾 | 手機還在用舊的「複製副本」安裝方式（git pull 不會生效） |
| （第 2 級）真的抓字幕 | YouTube、youtube-transcript-api、yt-dlp 是否正常 |
| （第 3 級）真的 AI 聽寫 | faster-whisper／whisper.cpp、模型、GPU 是否正常 |

### 看結果

```
  [通過] 主程式可以載入 —— ytscript.py 可以被載入（沒有語法錯誤）
  [失敗] 介面按鈕與後端一致
         原因：AssertionError: 介面按鈕 [...] 與後端 PROMPTS [...] 不一致
...
有 1 項失敗：介面按鈕與後端一致
→ 先不要 commit。把上面整段輸出貼給 AI，請它解釋原因。
```

- 最後一行是 `全部通過（N 項）` → 可以進行下一步
- 有任何 `[失敗]` → **不要 commit**。看「原因」那行；看不懂就整段貼給 AI（第 08 章提示詞 B 或 C）

### 2026-09-24 在桌機的實測結果

```
第 1 級：13 項全部通過
第 2 級：真的抓一部 YouTube 影片的字幕 —— 標題「Me at the zoo」，6 段
第 3 級：真的跑一次 AI 聽寫（tiny 模型） —— faster-whisper tiny，3 段；使用顯示卡加速（GPU．int8_float32）
全部通過（15 項）
```

另外以「假裝沒有 GPU」的方式測過 CPU 路徑（筆電會走的路），也能正常聽寫。
**手機尚未實測 selfcheck**，第一次在手機上跑時請記錄結果。

### 自我檢查的極限（要誠實知道）

它**不能**確認：
- 畫面看起來對不對（排版、顏色、深色模式）
- AI 分析的品質（提示詞改得好不好）
- 長影片的分份、非 YouTube 網站、特殊字幕格式的真實情況
- 手機的桌面小工具、PWA 圖示

這些要靠下面的手動測試。

## 3. 手動測試清單

### 測試影片清單（請自己建立並填寫）

準備一組「固定的測試影片」，每次測試都用同一組，才能比較前後差異。
**建議在這裡填好網址，commit 起來。**

| 類型 | 網址 | 預期結果 |
|---|---|---|
| 超短、有字幕（selfcheck 用的） | `https://www.youtube.com/watch?v=jNQXAC9IVRw` | 約 6 段字幕，人工字幕 · en |
| 中文、有人工字幕 | 【請填】 | 人工字幕 · zh-TW |
| 只有自動字幕 | 【請填】 | 自動字幕，輸出有「自動語音辨識」提醒 |
| 有章節 | 【請填】 | 輸出有「影片章節（作者標註）」 |
| 超過 1 小時 | 【請填】 | 出現「已自動切成 N 份」 |
| **完全沒有字幕**（短一點，5 分鐘內） | 【請填】 | 走 AI 聽寫；標籤顯示 faster-whisper 或 whisper.cpp |
| 非 YouTube（例如 bilibili） | 【請填】 | 平台欄顯示 BiliBili；簡體轉成繁體 |

### A. 每次改完程式（在桌機）

- [ ] `python tools/selfcheck.py` 全部通過
- [ ] 雙擊 `疑難排解.bat`，畫面正常打開
- [ ] 用「有字幕」的測試影片轉一次
- [ ] 三種分析模式各切換一次（會命中快取，很快）
- [ ] 「複製全部給 AI」→ 貼到記事本，內容正確
- [ ] 下載 .md 一次
- [ ] 如果改的是畫面：按 `F12` → `Ctrl+Shift+M` 切成手機尺寸看一次
- [ ] 如果改的是畫面：Windows 設定切成深色模式看一次

### B. 動到 AI 聽寫、GPU 或引擎時（加做）

- [ ] `python tools/selfcheck.py --whisper`：確認看到「使用顯示卡加速（GPU．int8_float32）」
- [ ] 用「完全沒有字幕」的測試影片，「快速」和「準確」各跑一次
- [ ] 用超過 1 小時的影片確認分份正常
- [ ] 用非 YouTube 影片跑一次

### C. 筆電（每次 git pull 之後）

- [ ] `git pull`
- [ ] `python tools/selfcheck.py` 全部通過；硬體路徑顯示 `CPU`
- [ ] 雙擊桌面捷徑，畫面正常
- [ ] 用「有字幕」的測試影片轉一次
- [ ] 如果這次更新動到 AI 聽寫：`python tools/selfcheck.py --whisper`（CPU 會比較慢）

### D. 手機（每次 git pull 之後）

- [ ] `cd ~/transcript && git pull`
- [ ] pull 訊息裡有 `android/install.sh` 或 `requirements/` 的變動 → `bash android/install.sh`
- [ ] `python tools/selfcheck.py`：全部通過；硬體路徑顯示 `Android／Termux`、whisper.cpp 與 ffmpeg 都找得到
- [ ] Termux 通知列按 Exit → 點桌面小工具重新啟動
- [ ] 手機瀏覽器畫面正常，輸入框與按鈕是上下排列
- [ ] 用「有字幕」的測試影片轉一次
- [ ] 「複製全部給 AI」→ 切到 ChatGPT App 貼上
- [ ] 如果這次更新動到 AI 聽寫：用「完全沒有字幕」的短影片跑一次

### E. 發布一個穩定版之前（三台都做完 A～D）

- [ ] 三台都通過
- [ ] `git tag -a v日期 -m "三台實測可用"` → `git push origin v日期`
- [ ] 升級過套件的話，把新版本號寫進 `requirements/`（第 10 章）
