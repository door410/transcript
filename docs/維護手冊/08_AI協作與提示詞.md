# 08　AI 協作維護流程與專用提示詞

> 對應原本需求的《26 如何讓 AI 幫我修改程式》《27 如何讓 AI 幫我除錯》《28 如何驗證 AI 給我的程式碼》與「第六、七階段」。

---

## 1. 「描述需求 → 免費 GPT 寫程式」這個方法合理嗎？

**合理，而且對這個專案特別合適。** 理由：

- 專案小（核心只有 2 個檔案），功能分區清楚
- 大部分修改是「改文字、加選項、調數字」，這正是 AI 最擅長、最不容易出錯的類型
- 有 `tools/selfcheck.py` 可以客觀驗證，不用靠「感覺」判斷 AI 對不對

**但有四個前提，缺一個就不安全：**

1. **AI 看不到你的整個專案。** `ytscript.py` 約 7.6 萬字元（估計 2～3 萬 tokens），免費版常常塞不下或讀不仔細。
   → 你要**只給相關的那一段**，加上一張「專案背景卡」（下面第 3 節）
2. **AI 很愛順手「改善」你沒要求的地方**（重新命名、重構、刪掉它覺得多餘的防呆）。
   → 提示詞要**明確禁止**，而且你要**看 diff**
3. **AI 會很有自信地說錯。** 特別是關於套件版本、CUDA、Termux 的事情。
   → **只相信 selfcheck 和實際執行的結果**，不相信 AI 說「這樣應該可以」
4. **AI 不知道那些「踩過的坑」。** 這個專案的註解裡記錄了很多「先前這樣寫結果壞掉」的經驗。
   → 給 AI 程式碼時**連註解一起給**，並要求它保留

## 2. AI 協作維護 SOP（依這個專案調整過的版本）

和你原本設想的流程相比，主要修正了三處：
**(a) 在給 AI 之前先開分支；(b) 讓 AI 分兩階段回答（先分析、你同意後才寫程式）；(c)「更新其他版本」不是改程式，而是 pull。**

```
 1. 寫下需求（一句話 + 不要動到什麼）
 2. 查第 02 章對照表：屬於哪個範圍（三台／GPU／手機）、要改哪些檔案與函式
 3. git switch main → git pull → git switch -c feature/名稱        ← 先上保險
 4. 準備給 AI 的材料：
      · 專案背景卡（第 3 節，每次都貼）
      · 相關函式的完整程式碼（含註解）
      · 如果動到畫面：ui.html 相關的 HTML 與 JavaScript
 5. 用「提示詞 A」→ AI 第一階段只回答：理解、位置、影響、風險、方案（不寫程式）
 6. 你檢查它的分析：
      · 它說要改的檔案和第 2 步查到的一致嗎？
      · 它有沒有提議改你沒要求的東西？ → 有就叫它拿掉
 7. 回覆「同意，請提供修改內容」→ AI 第二階段給程式碼
 8. 把修改貼進 VS Code
 9. git diff → 用第 6 節的檢查清單逐項看
10. python tools/selfcheck.py → 全部通過
11. 實際使用：新功能 + 至少一個舊功能
    ├─ 有問題 → 用「提示詞 C」回報給 AI（最多兩輪）
    └─ 兩輪還不行 → git switch main，放棄這條分支，換個方式描述需求
12. git add 檔名 → git commit -m "說明（依 GPT 建議）"
13. git switch main → git merge feature/名稱 → selfcheck
14. git push
15. 筆電、手機 git pull，重新啟動程式
16. 另外兩台各測一次（第 09 章）
```

## 3. 專案背景卡（每次開新對話都先貼這段）

> **為什麼需要它：** AI 每次都是從零開始，不知道你的專案長怎樣。
> 這張卡讓它在幾百字內知道架構與規則，避免它憑空想像、給出不相容的程式碼。
> **程式有大改時，記得更新這張卡**（可以用提示詞 G 請 AI 幫你更新）。

~~~text
【專案背景卡】（請先閱讀，之後的所有回答都必須遵守）

專案：YouTube 逐字稿工具。把影片連結轉成適合貼給 AI 分析的逐字稿。
GitHub：https://github.com/door410/transcript
維護者：程式零基礎，靠 AI 協助維護。請用繁體中文、白話解釋。

架構：本機網頁應用程式，沒有框架、沒有資料庫、沒有建置步驟。
- ytscript.py（Python，約 1,900 行）：核心。內含本機網頁伺服器（http.server，只綁 127.0.0.1:8756）、
  三層字幕引擎、輸出格式、快取。三台裝置共用同一份檔案。
- ui.html（HTML + 原生 JavaScript，無框架）：畫面。用 fetch 呼叫 /api/start、/api/status、/api/ping。
- tokens.css：設計系統（CSS 變數 --color-*、--space-*，元件 class 前綴 .fi-*）。

三台裝置（同一份 ytscript.py，執行時自己偵測）：
- 桌機 Windows + NVIDIA GPU：AI 聽寫用 faster-whisper + CUDA（pick_device() 判斷）
- 筆電 Windows 無獨顯：同上但走 CPU
- 手機 Android Termux：IS_TERMUX 為 True，AI 聽寫改用 whisper.cpp（engine_whispercpp，呼叫外部 whisper-cli）。
  手機直接執行 ~/transcript 裡的程式，~/ytscript/start.sh 只是啟動器。

主流程：transcribe() → 快取 → 引擎1 engine_transcript_api → 引擎2 engine_ytdlp
        → 防呆 has_caption_tracks → 引擎3 engine_whisper / engine_whispercpp
        → to_traditional（簡轉繁）→ cache_save → assemble()
assemble() 回傳的字典欄位（meta、sub_meta、markdown、plaintext、srt、parts、stats）
是 ui.html 讀取的「前後端約定」，不可改名或刪除。

分析模式：PROMPTS 字典（deep、quick）+ "none"。ui.html 的 segPrompt 按鈕 data-v、
PROMPT_HINTS 必須與 PROMPTS 的 key 一致。

維護規則（必須遵守）：
1. 只修改我要求的部分。不要重構、不要重新命名、不要調整排版、不要「順便改善」。
2. 保留所有既有註解，特別是寫著「先前」「實測」「注意」「陷阱」的註解 ——
   那些記錄的是實際踩過的坑，旁邊的程式碼是刻意這樣寫的。
3. 不要移除任何 try/except、防呆、fallback（例如 GPU 失敗改 CPU、套件沒裝就跳過）。
4. 不要新增套件，除非我同意。若必須新增，要告訴我 Windows 與 Android Termux 能不能裝。
   套件版本統一寫在 requirements/core.txt（三台）或 requirements/whisper.txt（只有電腦），
   三個安裝管道（安裝.bat、ensure_deps()、android/install.sh）都從這裡讀，不要把套件名稱寫死在腳本裡。
   requirements/*.txt 必須純 ASCII。
5. .bat 和 .vbs 檔必須維持純 ASCII（不能有中文，包含註解），換行為 CRLF。
6. Python 用「用到才 import」的方式載入外部套件。
7. 修改後我會執行 python tools/selfcheck.py 驗證，請告訴我應該特別注意哪幾項。
~~~

## 4. 提示詞模板

使用方式：**開新對話 → 貼背景卡 → 貼下面其中一個模板（把【】裡的內容換掉）→ 附上程式碼。**

### 提示詞 A：新增或修改功能（兩階段）

~~~text
【背景卡已貼在上面】

我想要：【一句話描述需求】
不要動到：【例如：原本的三種分析模式、手機版、GPU 相關程式】
我判斷要改的地方：【例如：ytscript.py 的 PROMPTS、ui.html 的 segPrompt 與 PROMPT_HINTS】

以下是相關程式碼（含註解，未經修改）：
【檔名 + 行號範圍】
```【貼上程式碼】```

請分兩階段回答。

【第一階段：現在只做這些，不要寫任何程式碼】
1. 用白話說明你理解的現有架構（這段程式碼在做什麼、被誰呼叫、它呼叫誰）
2. 你建議修改哪些檔案、哪些函式、大約哪幾行？我判斷的位置對不對？有沒有漏掉的地方？
3. 每一處為什麼要改
4. 這個修改會影響哪些其他地方？三台裝置（桌機GPU／筆電CPU／手機Termux）各自會受到什麼影響？
5. 風險：可能會壞掉什麼？
6. 修改完之後我應該怎麼測試？

我確認之後，會回覆「同意，請提供修改內容」。

【第二階段：我同意後才做】
- 對每一處修改，給我「修改前的原始程式碼」和「修改後的程式碼」，讓我能用搜尋找到位置後整段替換
- 只給需要修改的部分，不要重寫整個檔案
- 不要更動任何我沒要求的地方，包括空白、排版、變數名稱、註解
~~~

### 提示詞 B：除錯（我不知道錯在哪）

~~~text
【背景卡已貼在上面】

問題：【發生什麼事】
在哪台：【桌機GPU／筆電／手機】
怎麼重現：【做了什麼操作、用哪部影片（網址）】
什麼時候開始的：【例如：昨天 git pull 之後／更新套件之後／一直都這樣】
最近改了什麼：【沒改／改了 xxx】

錯誤訊息（完整，未刪減）：
```【貼上疑難排解.bat 視窗、Termux 畫面、或畫面紅框的完整文字】```

自我檢查結果：
```【貼上 python tools/selfcheck.py 的完整輸出】```

相關程式碼（錯誤訊息裡提到的函式）：
```【貼上】```

請：
1. 先判斷錯誤發生在哪一層：系統環境／啟動器／Python 程式／本機伺服器／畫面JavaScript／外部服務（YouTube、套件）／AI聽寫與硬體
2. 判斷這是「程式碼的問題」還是「環境或外部的問題」。如果是後者，請不要建議修改程式碼
3. 列出可能原因，由最可能到最不可能
4. 給我逐步確認的方法（我要執行什麼指令、看到什麼代表是哪個原因）
5. 確認原因之前，不要給我修改程式碼的方案
~~~

### 提示詞 C：AI 改完之後壞了

~~~text
【背景卡已貼在上面】

我依照你（或另一個 AI）的建議修改了程式，結果出現問題。

原本的需求：【】
修改內容（git diff 的完整輸出）：
```【貼上 git diff】```

修改後的狀況：【什麼壞了】
錯誤訊息：
```【貼上】```
自我檢查結果：
```【貼上 selfcheck 輸出】```

請：
1. 檢查這份 diff：有沒有改到需求以外的地方？有沒有刪掉原本的程式或註解？
2. 找出造成問題的具體那一行
3. 給出「最小」的修正：只修正錯誤，不要重新設計
4. 如果你認為原本的修改方向就是錯的，直接告訴我，我會放棄這次修改重來
~~~

### 提示詞 D：解釋程式碼（學習用）

~~~text
【背景卡已貼在上面】

我是程式零基礎，正在學習理解自己的工具。請解釋下面這段程式碼。

```【貼上一個函式】```

請用這個格式回答：
1. 一句話：這個函式在我的工具裡負責什麼？
2. 它從哪裡拿到資料？（參數是什麼、誰會呼叫它）
3. 它把結果交給誰？（回傳什麼）
4. 逐段白話說明（每 3～10 行一段，不要逐字翻譯語法）
5. 裡面有沒有「刻意這樣寫」的地方？（看註解）為什麼？
6. 如果我刪掉它，會發生什麼事？
7. 如果我想修改它，最可能要改哪裡？改了可能影響什麼？
8. 裡面出現的程式概念（例如 dict、try/except），只挑我理解這段需要的，各用一兩句話解釋

請不要改寫這段程式，也不要建議「更好的寫法」。
~~~

### 提示詞 E：合併衝突

~~~text
【背景卡已貼在上面】

git 合併時出現衝突。這是衝突的那一段（含 <<<<<<< ======= >>>>>>> 標記）：
```【貼上衝突區塊，前後各多給 10 行】```

<<<<<<< HEAD 到 ======= 是我本機的版本：它做的是【】
======= 到 >>>>>>> 是 GitHub 上的版本：它做的是【】
我想要的結果：【兩個都保留／只要其中一個／不確定】

請：
1. 說明兩個版本各自改了什麼
2. 給出合併後的程式碼（不含任何衝突標記）
3. 提醒我合併後要測什麼
~~~

### 提示詞 F：請另一個 AI 審查修改（第二意見）

> **強烈建議用在比較大的修改上。** 開一個**新的**對話（或用另一個 AI），讓它當審查者。
> 寫程式的 AI 通常不會發現自己的錯，換一個「沒有先入為主」的 AI 效果好很多。

~~~text
【背景卡已貼在上面】

你是審查者。另一個 AI 為了下面這個需求修改了我的程式。請嚴格檢查這份修改，不要客氣。

需求：【】
修改（git diff）：
```【貼上】```

請逐項檢查並回報：
1. 修改有沒有超出需求範圍？（重構、改名、改排版、改註解、「順便」的改善）
2. 有沒有刪除原本的 try/except、fallback、防呆、註解？
3. 有沒有違反背景卡的任何一條維護規則？
4. 三台裝置（桌機GPU／筆電CPU／手機Termux）是否都相容？特別是手機能不能執行
5. 有沒有明顯的錯誤：語法、縮排、少逗號、名稱打錯、欄位名稱和 ui.html 對不上
6. 結論：可以接受／需要修正（列出）／應該整個重做

只找問題，不要重寫程式。
~~~

## 5. 怎麼準備要貼給 AI 的程式碼

### 貼一個完整的函式

1. VS Code 裡 `Ctrl+F` 搜尋 `def 函式名`
2. 從 `def` 那一行開始選，一直選到**下一個 `def` 的上一行**（或下一個 `# ====` 分隔線）
3. 函式上方如果有相關的大寫常數或註解，一起選
4. 貼上時註明「`ytscript.py` 第 xxx～yyy 行」

### 貼畫面相關的程式

`ui.html` 要一起給 AI 的通常是兩段：
- HTML：那個按鈕或區塊（搜尋 `id="..."`）
- JavaScript：處理它的程式（搜尋 `$('#那個id')`）

### 貼錯誤訊息

**完整貼，不要自己刪減或摘要。** 你覺得不重要的那幾行，常常正是關鍵。

### 貼 diff

```bash
git diff > 修改.txt
```

然後打開 `修改.txt` 複製全部（或直接從終端機複製）。
用完把 `修改.txt` 刪掉，不要 commit 它。

> 提示詞裡的 ```` ```【貼上】``` ```` 意思是：把內容貼在一對三個反引號之間。
> 這樣 AI 會把它當成「原封不動的程式碼」，不會誤讀格式。

## 6. 驗證 AI 給的程式碼：檢查清單

### 貼上之前

- [ ] AI 第一階段說要改的檔案，和我從對照表查到的一致
- [ ] AI 沒有提議「順便重構」「改善命名」「簡化」
- [ ] AI 給的是「修改前 → 修改後」，而不是一整個重寫的檔案
- [ ] 如果 AI 說要新增套件：我有同意，而且它說明了手機能不能裝

### 貼上之後（看 `git diff`）

- [ ] **改動的檔案數量** 符合預期（`git diff --stat`）
- [ ] **刪除的行數** 合理。刪除遠多於新增 → 高度可疑
- [ ] **沒有被刪掉的註解**，特別是「先前」「實測」「注意」
- [ ] **沒有被刪掉的 `try:` / `except` / `finally:`**
- [ ] **縮排**和上下文對齊（Python）
- [ ] **逗號、括號**成對（JavaScript）
- [ ] 名稱一致：`data-v="xxx"`、`PROMPTS["xxx"]`、`PROMPT_HINTS.xxx` 三處相同
- [ ] `.bat`／`.vbs` 沒有出現中文

### 執行驗證

- [ ] `python tools/selfcheck.py` 全部通過
- [ ] 新功能實際用一次，結果符合需求
- [ ] **至少一個舊功能**實際用一次，沒有被影響
- [ ] 如果動到 AI 聽寫：`python tools/selfcheck.py --whisper`
- [ ] 如果動到畫面：桌機 + 手機尺寸都看；淺色 + 深色模式都看

### AI 回答中的警訊

| AI 說 | 代表 | 你該做 |
|---|---|---|
| 「我幫你重構了一下，讓程式更簡潔」 | 它改了你沒要求的東西 | 要求它只做需求內的修改 |
| 「這個 try/except 是多餘的，我移除了」 | 它刪了防呆 | 拒絕。那是刻意的 |
| 「以下是完整的 ytscript.py」 | 它重寫了整個檔案，可能漏掉東西 | 要求只給修改的部分 |
| 「這樣應該就可以了」 | 它沒辦法驗證 | 你自己跑 selfcheck 驗證 |
| 「你需要安裝 xxx 套件」 | 新依賴 | 問它 Termux 能不能裝；三處安裝腳本要改 |
| 「建議改用 React / Flask / FastAPI」 | 它要改架構 | 拒絕。這個專案刻意不用框架 |
| 前後兩次回答說法矛盾 | 它在猜 | 用 selfcheck 和實際執行判斷，不要相信任何一次 |

## 7. 你不能交給 AI 的事（再強調一次）

1. **開分支／commit**：AI 不會替你記得

3. **看 diff**：這是你唯一能確認「AI 做了什麼」的方法
4. **判斷輸出好不好**：例如提示詞改完，AI 分析的品質有沒有變好，只有你能判斷
5. **決定要修還是要退**
