# YouTube 逐字稿 → AI

把知識型 YouTube 影片變成**為 AI 分析最佳化**的逐字稿，不用看完影片就能高效吸收重點。

**電腦與手機都能用。全程在自己電腦執行，無帳號、無 API key、無費用。**

---

## 怎麼用

### 電腦

**雙擊桌面上的「YouTube 逐字稿工具」圖示。**

瀏覽器會自動打開，沒有任何黑色視窗。貼上連結 → 按「開始轉錄」→ 按「複製全部給 AI」→ 貼到 Claude／ChatGPT／Gemini。

要結束程式：點網頁最下方的「結束程式」。

### 手機（兩種方式）

**方式一：手機獨立運行（推薦，不需要開電腦）**

Android 可以用 Termux 把整套程式裝進手機，功能與電腦版完全一致。
桌面放一個圖示，點一下就開。詳細步驟見 **[Android手機安裝說明.md](Android手機安裝說明.md)**。

之所以可行，是因為 YouTube 封鎖的是機房 IP，而手機的 4G／5G／WiFi 屬於住宅等級 IP，不受影響。

**方式二：連到電腦（電腦要開著）**

1. 電腦上先點開桌面圖示
2. 網頁下方會顯示 **`在手機上使用：http://192.168.x.x:8756`**
3. 手機連到**同一個 WiFi**，用瀏覽器打開那個網址

建議在手機上「加入主畫面」，就會變成一個 App 圖示。

> 想在外面也能用手機連回家裡的電腦？安裝免費的 [Tailscale](https://tailscale.com)（電腦和手機各裝一次），之後用 Tailscale 給的 IP 取代上面的網址即可。

## 為什麼輸出格式是這樣設計的

這是整個工具的核心。把逐字稿餵給 AI 時，格式的影響比大多數人想的大得多。

### 段落級時間戳（不是逐行）

逐行時間戳會讓 1 小時的影片多出**約 3 萬個 token 的純噪音**，還把句子切碎、破壞語意連貫性，AI 的理解品質反而下降。

完全不標時間戳，則會失去**可驗證性**——AI 說「他在這裡提出核心論點」，你沒辦法回去確認。而自動字幕有錯字，AI 也可能誤讀，你必須能查證。

本工具合併成**約 45 秒一段的語意段落**，每段開頭標一個時間戳。Token 成本降到 1/30，可驗證性完全保留。AI 能寫出「`[12:34]` 他提出第二個論點」，你點一下就回到原片。

### 影片後設資料

標題、頻道、發布日期、影片長度。沒有這些，AI 等於在真空中讀一堆文字，無法判斷領域、立場與時效性。

### YouTube 章節

如果影片有章節，工具會完整抓下來。**這是作者親手標註的結構**，是整部影片資訊密度最高的部分，對 AI 建立全局理解幫助極大。

### 影片簡介欄（已移除）

曾經會抓，後來拿掉了。實際的 YouTube 簡介幾乎都是聯盟行銷連結、邀請碼、
交易所推薦與 SEO 關鍵字堆砌，靠關鍵字黑名單永遠追不上新的變形 ——
濾完只會剩下被拔掉網址的業配標題，等於把廣告文餵給 AI。
真正有結構價值的是上面的「影片章節」，那是另外抽的，不受影響。
需要原始簡介時請自行到影片頁面複製。

### 字幕品質標註

明確告訴 AI「這是自動語音辨識產生的」，AI 才知道要容忍錯字、靠上下文推斷，而不是照字面死摳。

### 內建分析提示詞

輸出最前面附上一段設計過的指示，**複製後直接貼給 AI 送出就好，不用自己想怎麼問。**

「深度學習」模式的提示詞建立在四個原則上：

**1. 分層，避免作者觀點與 AI 觀點混在一起**
第一部分嚴格忠實還原影片（禁止 AI 加入判斷），第二部分才是 AI 的解讀，並明確標示。
否則你讀完會分不清哪句是作者說的、哪句是 AI 腦補的——這對「學習影片內容」是致命的。

**2. 保留作者原本的結構，不讓 AI 重新分類**
明確要求「依作者原本的講述順序重建架構，不要用你自己的分類重組」。
作者的鋪陳順序本身就是他思路的一部分，被重排就失真了。

**3. 抓「思考方式」，不只抓結論**
結論會過時、會被推翻；作者**如何拆解問題、用什麼心智模型切入**才是能遷移到
其他領域的資產。提示詞裡特別要求 AI 在這項多著墨。

**4. 強迫主動回憶，打破「我懂了」的錯覺**
讀摘要很容易產生理解的錯覺。提示詞要求 AI 出 5 個自我檢測題但**不附答案**，
只給時間戳，逼你自己回去找。再加上一個「今天就能做、不超過 30 分鐘」的具體行動，
讓學習落地而不是停在「覺得很有道理」。

## 介面上的選項（只有兩個）

| 選項 | 說明 |
|---|---|
| **分析模式** | 深度學習（預設）／快速摘要／純逐字稿 |
| **沒字幕時用 AI 聽寫** | 決定要不要花時間與流量處理無字幕影片 |

其餘參數經過實測，對輸出幾乎沒有影響，已固定成最佳值不再開放選擇：
時間戳段落級、段落 45 秒、清理贅詞、附上影片資訊。

### 為什麼砍掉那些選項（實測數據）

| 原選項 | 實際影響 | 結論 |
|---|---|---|
| 段落長度 30/45/75 秒 | **逐字稿文字一字不差**，只有換行位置不同；token 差 0.3〜0.5% | 純裝飾 |
| 時間戳關閉 | 只省 1.4% token，卻失去回查原片的能力 | 得不償失 |
| 簡介欄（完整或過濾） | 兩種都只多出推廣雜訊 | 已整個移除 |
| 清理贅詞關閉 | 多 3% 雜訊 token | 沒人會想關 |
| 影片資訊關閉 | 省 4.6% token，但失去標題／章節／日期 | 省小失大 |
| **分析模式** | **−779 / −1005 tokens，輸出結構完全不同** | **保留** |

### AI 聽寫模型：自動選擇，不開放手動

實測（18.7 分鐘影片）：

| 模型 | 大小 | 處理時間 | 與 small 的分歧率 |
|---|---|---|---|
| `tiny` | 75 MB | 1 分 05 秒 | 5.6% |
| `base` | 142 MB | 1 分 42 秒 | 4.9% |
| `small` | 466 MB | 4 分 27 秒 | 基準 |

**`base` 被 `tiny` 完全支配**——只好 0.7 個百分點卻慢 1.5 倍，因此不使用。
程式自動選擇：**電腦用 `small`，手機用 `tiny`**。

想改用更快的模型，修改 `ytscript.py` 的 `default_model_size()` 即可。

---|---|
| **分析模式** | **深度學習**（預設）／快速摘要／純逐字稿。見下方說明 |
| **時間戳** | 段落級（建議）／不要 |
| **段落長度** | 30 秒（細）／45 秒（適中）／75 秒（粗）。長影片想省 token 就選粗的 |
| **附上影片資訊與章節** | 預設開。**強烈建議保持開啟** |
| **清理贅詞與雜訊** | 移除 um／呃／嗯、`[音樂]` 標記與重複行 |
| **沒字幕時用 AI 聽寫** | 需另外安裝，見下方 |

### 三種分析模式

| 模式 | 適用時機 | 額外 token |
|---|---|---|
| **深度學習** | 知識思考型影片，想真正學會並內化 | 約 +950 |
| **快速摘要** | 想先判斷這部影片值不值得深入 | 約 +170 |
| **純逐字稿** | 你想自己下提示詞 | 0 |

輸出格式：**`.md`**（推薦，格式最完整）、**`.txt`**（純文字）、**`.srt`**（影片字幕檔）。

## 運作原理：三層自動接力

| 層 | 方法 | 速度 | 何時啟動 |
|---|---|---|---|
| 1 | `youtube-transcript-api` | 1～3 秒 | 一律先試 |
| 2 | `yt-dlp` | 3～10 秒 | 第 1 層被擋時 |
| 3 | `faster-whisper` 本機 AI 聽寫 | 數分鐘 | 影片完全沒字幕時 |

前兩層只是把 YouTube 伺服器上**已經存在**的字幕取下來，不下載影片，所以極快。影片後設資料在背景平行抓取，不額外花時間。

## 流量用多少？（實測數據）

**這個工具不會像看影片那樣耗流量。** 以一部 18.7 分鐘的影片實測：

| 使用方式 | 流量 | 相當於 |
|---|---|---|
| **影片有字幕**（多數知識型頻道） | **約 0.2 MB** | 1 GB 可處理約 **5,000 部** |
| **沒字幕，AI 聽寫（省流量模式）** | **約 6.2 MB** | 1 GB 可處理約 **165 部** |
| 沒字幕，AI 聽寫（未開省流量） | 約 20 MB | — |
| 對照：用 360p 看完整部 | 約 90 MB | — |
| 對照：用 720p 看完整部 | 約 250 MB | — |
| 對照：用 1080p 看完整部 | 約 575 MB | — |

有字幕時只抓純文字，流量是看 360p 的 **1/450**。
就算要 AI 聽寫，省流量模式也只有看 360p 的 **1/14**。

### 省流量模式做了什麼

Whisper 一律把音訊重新取樣成 **16kHz 單聲道**，所以高位元率音源對辨識準確度
幾乎沒有幫助，卻會多耗好幾倍流量。省流量模式會挑位元率最低的音軌：

實測同一部影片：**45 kbps opus = 6.0 MB**，而非預設的 **134 kbps = 17.9 MB**，
省下 **70%**。這個選項預設就是開啟的。

### ⚠️ 一次性的安裝流量（建議在有免費 WiFi 的地方做）

| 項目 | 大小 | 說明 |
|---|---|---|
| faster-whisper 套件（電腦） | 123 MB | 只裝一次 |
| 模型 `tiny` / `base` / `small` | 75 / 142 / 466 MB | 只下載一次，之後永久離線 |

**如果你的行動數據有限，強烈建議在學校、圖書館或咖啡廳的免費 WiFi 完成這一次安裝。**
裝完之後日常使用就只有上表的流量了。

## AI 聽寫（影片完全沒字幕時）

**這不會破壞「永久免費」，反而是這個工具最耐用的一層。**

| 項目 | 事實 |
|---|---|
| 授權 | faster-whisper、whisper.cpp、Whisper 模型全部是 **MIT 授權** |
| 費用 | **零**。沒有 API key、沒有帳號、沒有配額、沒有服務商能關掉它 |
| 網路 | 只有第一次下載模型需要。**之後永久離線可用** |
| 隱私 | 音訊不會上傳到任何地方，全部在你的裝置上運算 |
| 成本 | 付出的是 **CPU 時間與硬碟空間**，不是錢 |

它比第 1、2 層更耐用：前兩層依賴 YouTube 的字幕介面（YouTube 改版就可能壞掉），
第 3 層只需要音訊，**只要影片還能播放就永遠有效**。

### 運作過程（完全不涉及外部服務）

1. yt-dlp 只下載**音訊**（20 分鐘影片約 5～20 MB，不是整部影片）
2. 解碼成 16kHz 單聲道
3. VAD 語音偵測，自動略過靜音段
4. Whisper 模型以 30 秒為單位處理，輸出文字與時間戳
5. 合併成段落

第 2～5 步完全不連網。

### 電腦端安裝

```bash
pip install faster-whisper
```

**不需要另外裝 ffmpeg** —— faster-whisper 內含 PyAV 解碼器。

### 手機端（Android）：必須用 whisper.cpp

⚠️ **`faster-whisper` 在 Android 上裝不起來。**
它依賴的 CTranslate2 沒有發布 Android ARM64 預編譯套件，pip 會試圖從原始碼編譯而失敗。

手機要用這個：

```bash
pkg install ffmpeg
pip install termux-stt
```

`termux-stt` 內含**預編譯好的 ARM64 whisper.cpp 執行檔**，不需要自己編譯。
程式會自動偵測環境：手機用 whisper.cpp，電腦用 faster-whisper。

### 模型大小怎麼選

| 模型 | 大小 | 建議 |
|---|---|---|
| `tiny` | 75 MB | 手機預設。最快，同音字錯誤較多 |
| `base` | 142 MB | 折衷 |
| `small` | 466 MB | **電腦預設**。中文表現明顯較好 |
| `medium` | 1.5 GB | 最準，但一般筆電上可能比影片本身還久 |

介面上可以手動切換。模型只下載一次，存在 `~/.cache/whisper-cpp`（手機）
或 Hugging Face 快取（電腦）。

### 務實的期待

AI 聽寫**慢**。有字幕的影片幾秒就好，沒字幕的可能要數分鐘到數十分鐘。
所以工具的設計是三層接力：**有現成字幕就用（快），沒有才聽寫（慢但免費）**。

## 支援哪些平台？

不只 YouTube。第 2、3 層引擎用的是 **yt-dlp，支援上千個網站**：
Bilibili、X／Twitter、TikTok、Twitch、Dailymotion、Podcast RSS、各種新聞網站等。

- **YouTube**：走專用快速通道，最快也最完整（章節、多語字幕）
- **其他平台**：自動交給 yt-dlp。有字幕就抓字幕，沒有就 AI 聽寫

⚠️ **誠實提醒**：「支援上千個網站」不等於「每個都能用」。
各平台的政策不同——例如 Vimeo 現在多數影片要求登入才能存取。
遇到抓不到的平台，通常是該站需要登入或有地區限制，不是工具壞了。

## 常見問題

**突然抓不到了？** 先跑這行，九成問題會解決：

```bash
python -m pip install --upgrade yt-dlp youtube-transcript-api
```

**不要掛 VPN，不要放雲端主機。** YouTube 大量封鎖機房 IP（AWS／GCP／Azure），用家用網路反而最穩定。這也是為什麼這個工具設計成在你自己電腦上跑。

**真的無法取得的情況：** 私人／會員限定／已刪除的影片；創作者關閉字幕且沒有自動字幕（這種要靠第 3 層 AI 聽寫）。

**短時間查太多次** 可能被暫時限流，等幾分鐘再試。

**關於「永遠免費」**：費用上是真的——沒有 API key、沒有配額、沒有服務商能關掉它。可用性上，YouTube 偶爾改版可能弄壞第 1、2 層，但第 3 層完全離線，**只要影片還能播放就永遠有效**。

| 檔案 | 用途 |

| `android/` | Android（Termux）安裝腳本與說明 |

### 單檔版與手機安裝包

Android 上搬一堆檔案很麻煩，所以另外提供把所有資源內嵌進去的單一 `.py`。
**不要手動編輯它** —— 它是產生出來的：

```
python build/make_single_file.py
```

產物在 `dist/`（不進版控）：`逐字稿工具_單檔版.py` 與 `手機安裝包.zip`。
改介面請改 `ui.html` / `tokens.css` 再重新產生。

> 以前這個單檔版是手動複製維護的，結果同一個 bug 要修兩次 —— 而且真的漏過。
> 現在它從本體產生，本體修好就自動跟上。

> **給未來的我／任何要改這個專案的人：**
> `.vbs` 和 `.bat` 檔**必須維持純 ASCII 內容**。這台電腦的系統代碼頁是 950（Big5），
> Windows 用 ANSI 代碼頁讀取這兩種檔案，UTF-8 的中文位元組會被 Big5 前導位元組
> 吃掉換行符號，導致整個檔案斷行錯亂、片段被當成指令執行。
> 中文訊息請放在 `ui.html` 或 Python 檔裡（那些明確宣告 UTF-8，沒有這個問題）。

### 命令列模式

```bash
python ytscript.py "網址"         # Markdown（預設）
python ytscript.py "網址" --txt   # 純文字
python ytscript.py "網址" --srt   # SRT 字幕
python ytscript.py "網址" > 筆記.md
```

## 關於網路存取

程式會監聽 `0.0.0.0:8756`，讓同一個區域網路內的手機能連上。這表示**同一個 WiFi 下的其他裝置也能開啟這個頁面**。在家用網路通常沒問題；如果你在公共 WiFi 或不希望如此，把 `ytscript.py` 裡的 `("0.0.0.0", port)` 改成 `("127.0.0.1", port)`，就只有本機能用（手機功能會關閉）。
